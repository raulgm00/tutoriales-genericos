Convertir Ubuntu en la Fábrica

Cómo le dices a Claude, recién instalado en Ubuntu, quién es, para quién trabaja y a quién le reporta · 20 minutos + tus secretos

La pregunta que responde esta guía: "ya entré a Ubuntu… ¿cómo le digo a Claude que esta máquina es la fábrica, que el centro de operaciones es la Mac y que debe reportar al Monitor?". Respuesta corta: Claude no adivina nada; lee tres cosas al arrancar: un archivo de identidad (~/.claude/CLAUDE.md), su memoria (~/.claude/projects/…/memory/) y un hook de inicio (SessionStart). Esta guía deja las tres puestas con un solo script.
🗺️ Quién es quién 📖 Qué lee Claude 🐧 Pasos en Ubuntu 🔐 Tus secretos ✅ Verificar ⚠️ Límites ⬇️ Archivos

1 · Quién es quién en tu sistema

Tres máquinas, tres papeles. Ubuntu no manda: trabaja. Y no guarda el registro: lo publica.

Los tres "padres" (Mac, Ubuntu, Windows) alimentan el mismo Monitor en la nube. Por eso el Monitor no se instala en Ubuntu: Ubuntu solo aprende a publicar en él.

2 · Qué lee Claude al arrancar (y por eso "sabe" que es la fábrica)

Nada de esto es magia ni se le "dice en el chat" cada vez. Son archivos que Claude Code carga solo en cada sesión.

Dónde queda la memoria: Claude Code guarda la memoria por carpeta de proyecto. La carpeta "home" de Ubuntu (/home/USUARIO) se codifica como -home-USUARIO. El script calcula ese nombre solo; no lo escribas a mano.

3 · Pasos dentro de Ubuntu

Requisito: ya arrancas Ubuntu desde GRUB (si no, primero la guía Dual-boot: GRUB y reloj). Abre una terminal con Ctrl+Alt+T.

1

Montar el disco de Windows (C:) en /mnt/c

Todo lo que Ubuntu necesita (credenciales, memoria, skills, el repo de conocimiento, tus repos) ya está en el disco de Windows. No se copia nada a mano: se monta y se lee de ahí.

sudo mkdir -p /mnt/c && sudo mount -t ntfs3 -o uid=$(id -u),gid=$(id -g) /dev/nvme0n1p2 /mnt/c
  • ntfs3 es el driver NTFS que trae el kernel de Ubuntu 24.04 (lee y escribe).
  • uid/gid hace que los archivos aparezcan como tuyos (si no, todo sale como root).
  • Si falla: C: puede ser /dev/nvme1n1p2. Míralo con lsblk -o NAME,SIZE,FSTYPE,LABEL: C: es la partición NTFS de 1.88 TB.
Si dice "volume is dirty" o no monta: Windows quedó hibernado (Inicio rápido). Arranca Windows, apágalo del todo (no reinicio) y vuelve. En tu PC el Inicio rápido ya está apagado.
2

Correr el script de primer arranque

bash /mnt/c/tmp/arranque-ubuntu/02-primer-arranque-claude.sh

Es idempotente (se puede repetir sin romper nada: solo copia lo que falta) y nunca pide ni imprime secretos. En orden:

3

Rellenar tus tres secretos (solo tú)

El script deja en ~/.bashrc un bloque entre >>> monitor-wesoft >>> y <<< monitor-wesoft <<< con las variables vacías. Ábrelo con nano ~/.bashrc y rellena:

VariableDe dónde sale
CF_ACCESS_CLIENT_ID / CF_ACCESS_CLIENT_SECRETCloudflare Zero Trust → Credenciales de servicio → crear token monitor-ubuntu y autorizarlo en la política Maquinas (igual que hiciste con monitor-mac).
MONITOR_SECRETS_PASSPHRASELa misma frase que usan Windows y la Mac: es la llave del cifrado extremo a extremo de "Tareas Diarias". Sin ella, Ubuntu no puede leer ni escribir puntos de regreso.

Guarda (Ctrl+O, Enter, Ctrl+X) y abre una terminal nueva para que carguen.

Nunca pegues estos valores en un chat con Claude ni los metas en el repo de conocimiento. Claude los usa desde el entorno; no necesita verlos.

5 · Límites y avisos honestos

  • La partición de Ubuntu quedó de 24 GB (se pidieron 250–400). Alcanza para arrancar, Claude y pruebas; no para imágenes Docker/Incus con varios obreros. Antes de escalar: encoger C: y ampliar/mover la partición con GParted desde el USB de instalación, o montar /var/lib/docker en otra partición.
  • Dual-boot = uno solo encendido. Mientras Ubuntu trabaja, todo lo que vive en Windows (tareas programadas, vigías, mineros) está apagado. Lo que deba ser 24/7 tiene que migrar a Ubuntu (unit systemd) o a la nube; el Monitor ya está en la nube.
  • GPU: la RTX 5070 Ti necesita el driver nvidia-driver-580-open. Los pantallazos de Windows son de plataforma (fuente/EXPO) y en Linux reaparecerían como Xid 79: no es "bug de Ubuntu".
  • Repos con enlaces: las academias usan 43 junctions de Windows hacia D:/F:. En Ubuntu hay que montar esas unidades y recrearlos como symlinks (los videos no se mueven). Pendiente.
  • Rutas dentro de las skills: vienen con C:\…; el CLAUDE.md le dice a Claude que las traduzca a /mnt/c/….
